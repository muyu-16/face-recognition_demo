## 三、安装

### 方式 A：用 uv（推荐，最快、最不容易踩坑）

[uv](https://docs.astral.sh/uv/) 是新一代 Python 包管理器，一条命令搞定「建环境 + 装依赖」，
而且能绕开下面这两个常见坑（**很多同学的机器都会遇到**）：

- **坑 1**：Python 由 uv / conda 托管时，`pip install` 会被拒绝：
  `error: externally-managed-environment (PEP 668)`；
- **坑 2**：这类 Python 执行 `python -m venv` 时无法 bootstrap pip，
  建出来的 `.venv` **里面根本没有 pip**（报 `No module named pip`）。

安装 uv（Windows，无需管理员权限）：

```powershell
powershell -c "irm https://astral.sh/uv/install.ps1 | iex"
```

然后在本项目根目录执行：

```bash
cd 人脸识别大作业
uv venv .venv --python 3.11          # 建虚拟环境（用 Python 3.11）
uv pip install -r requirements.txt   # 装依赖，uv 会自动装进 .venv
```

国内网络慢时换镜像：

```bash
uv pip install -r requirements.txt --default-index https://pypi.tuna.tsinghua.edu.cn/simple
```

### 方式 B：用标准 python.org 的 Python + pip

如果你的 Python 是从 python.org 安装的（不是 uv / conda 托管的），可以用传统方式：

```bash
cd 人脸识别大作业
python -m venv .venv
# Windows
.venv\Scripts\activate
# Linux / macOS
source .venv/bin/activate

pip install -r requirements.txt
# 国内镜像：pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

> 提示：激活虚拟环境后提示符前面会出现 `(.venv)`。
> 一定要确认「装依赖」和「运行程序」用的是**同一个解释器**，
> 否则会出现"明明装了却说没有这个模块"。

### 方式 C：一键脚本（Windows 偷懒法）

直接双击 **`run.bat`**：它会自动识别 `uv` 或 `py 3.10~3.12`、建虚拟环境、装依赖、跑自检、启动界面。
只想看看它会做什么而不真的安装：`run.bat --dry-run`。

> `run.bat` 内部刻意只用 ASCII 英文提示：cmd.exe 按系统 OEM 代码页解析 .bat 文件，
> UTF-8 中文会被解码错乱，导致 `&&`、引号等被吃坏、脚本直接崩掉（这是实测踩过的坑）。

先按 `nvidia-smi` 里的 CUDA 版本，到 <https://pytorch.org/get-started/locally/> 选对应命令，例如 CUDA 12.1：

```bash

# 用 uv 的话：uv pip install torch torchvision --default-index https://download.pytorch.org/whl/cu121
```

## 五、使用流程（现场演示 5 分钟版）

### 1️⃣ 注册人员（≥5 张，按机位拍）

1. 打开「🧑‍🎓 人员注册」标签页，**先填姓名**（不填姓名不会保存，见下）；
2. 按 **7 机位黄金录入标准**采集（界面会实时告诉你"再转几度"）：
   **正脸 0° → 左半侧 15°~30° → 右半侧 15°~30° → 轻微抬头 10°~15° → 轻微低头 10°~15°
   → 左大侧 45°~60° → 右大侧 45°~60°**；
3. 采集方式三选一（都按上面这套 7 机位标准判定）：
   - **🎥 浏览器实时录入（WebRTC，推荐）**：点 START 允许摄像头后站好，
     浏览器把视频流推给 Python，**画面里实时叠加**人脸框、实测角度、
     `core=x/7` 和 `NEXT: half_left (yaw 15-30 deg)`；**达标后自动保存**
     （不需要再点任何按钮），再点注册即可（详见下面「浏览器实时录入」）；
   - **📷 摄像头拍照（连拍）**：点一次快门就自动存入采集列表，每张立刻做「体检 + 机位识别」，
     并告诉你这张是多少度、下一张该拍什么；完全重复的照片会自动忽略；
   - **📁 上传图片**：一次选中同一人的 5 张以上照片（建议就按 7 机位标准各来一张）；
4. 可先点「🔍 仅检测预览」确认每张图都能检测到人脸；
5. 点「🚀 提取特征并注册」，界面会逐张显示处理结果，成功后会提示库内特征条数。

> 少于 5 张有效人脸会**拒绝注册**并说明原因（例如"未检测到人脸"），这是作业的硬性要求；
> 按 7 机位标准采集则能同时满足覆盖度要求。

#### 🎥 浏览器实时录入（WebRTC，`live_enrollment.py`）

**怎么用**：选「🎥 浏览器实时录入（WebRTC）」→**先在「① 姓名」填好名字**（必须）→
点 **START** → 浏览器弹窗点**允许** → 站到镜头前，**跟着画面上的提示慢慢转头**
（提示直接画在视频里，不用来回看网页）→ **达标后自动保存**，下方出现这些帧和覆盖表 →
点「🚀 提取特征并注册」。

**两条内置规则**：

| 规则 | 行为 |
| --- | --- |
| **必须先填姓名** | 没填姓名时**不会保存**（自动/手动都不行），页面会一直提示"请先在①处输入姓名"；填完名字后，已经采集好的帧会**立刻自动保存**，不用重新拍 |
| **达标自动保存** | 状态区每 0.5 秒刷新一次（`st.fragment(run_every=0.5)`），一旦达标就把帧冻结到 `session_state`，之后按 STOP 也不会丢 |

**达标条件可在「⚙️ 自动保存设置」里选**（默认第一条）：

| 条件 | 含义 |
| --- | --- |
| 集齐 5 个核心机位 | 正面/左转/右转/抬头/低头各一张即保存（最快） |
| 集齐且**平均**质量分 ≥ 门槛 | 除了齐全，还要求平均质量分达到设定值（默认 80 分） |
| 集齐且**每张**都达标 | 最严格：每一张的机位质量分都要过门槛 |

也可以关掉自动保存，改用「✅ 采集完成，取用这些帧」手动保存（同样要求先填姓名）。

**技术要点**：

- 视频处理器的工厂函数用 `functools.partial`（可 pickle），模型在处理器内部自建，
  避免跨进程序列化 PyTorch 模型；
- 模式固定为 **`async_processing=False`**：这样处理器与主脚本**同进程**，
  主脚本才能通过 `ctx.video_processor` 把它采集到的帧取出来入库
  （用独立进程时取不到，这是 streamlit-webrtc 的设计）；
- **检测跑在后台线程**（见下"性能优化"），`recv()` 只负责转发画面；
- 自动保存写在 `st.fragment` 里：它只**读**处理器状态，只在"达标且还没保存过"时
  **写一次** `session_state`；保存完成之后定时刷新会自动停掉，省 CPU、也不再重复传图。

##### 性能优化：为什么"刚开摄像头会卡一下"

旧版把 MTCNN 直接放在 `recv()` 里跑：一帧要 **0.3~0.6 秒**（CPU），
而浏览器每秒推 20~30 帧 → 处理不过来就**排队积压**，
表现就是"刚开流那几秒又卡又延迟"，等浏览器拥塞控制把码率降下来才"看起来不卡了"。

现在做了四件事：

| 优化 | 说明 |
| --- | --- |
| **检测移到后台线程** | `recv()` 只把当前帧丢进"只保留最新一帧"的槽位就立刻返回；模型慢慢跑，画面永远不等它。处理不过来时**自动丢旧帧**，不会越积越卡 |
| **模型全进程共用 + 启动预热** | 旧版每次开流都 `FaceDetector(...)` 新建一个模型；现在复用 `app.py` 已加载的实例，并在应用启动时用一张空白图**预热**，把 PyTorch 第一次前向（惰性初始化，0.5~2 秒）的开销提前付掉 |
| **推流参数收敛** | `640×480`、`frameRate ideal 24`。MTCNN 耗时大致与画面面积成正比，避免浏览器默认推 1080p |
| **保存后停掉定时刷新** | 达标保存后 `run_every=None`，不再每 0.5 秒重传已保存的图片 |

实测（模拟"检测每帧 300ms、浏览器 30 FPS 推流 60 帧"）：

| 指标 | 优化前 | 优化后 |
| --- | --- | --- |
| `recv()` 平均耗时 | ≥300 ms（等于模型耗时） | **5.4 ms** |
| 首帧耗时 | >1000 ms（含模型加载/初始化） | **24.1 ms** |
| 处理不过来时 | 排队积压 → 越来越卡 | 丢旧帧（丢 51 帧），永远分析最新画面 |

> 剩下那 1~2 秒是 WebRTC **建立连接**本身的时间（可能先黑一下），属于正常现象。

**打不开摄像头**：必须用 `http://localhost:8501` 打开页面；用局域网 IP 时浏览器会
**直接禁用**摄像头（连弹窗都不会出现）。误点过「阻止」后弹窗也不会再出现，
需要在地址栏左侧的网站设置里把摄像头改回「允许」并刷新页面。

| 方式 | 谁在读摄像头 | 需要浏览器授权 | 流畅度 | 说明 |
| --- | --- | --- | --- | --- |
| 📁 上传图片 | — | 否 | — | 最省事，不依赖摄像头 |
| **🎥 浏览器实时录入（WebRTC）** | 浏览器 | **是** | 最流畅（~20 FPS） | 边看画面边按提示转头，自动覆盖 5 个机位 |
| 📷 摄像头拍照（连拍） | 浏览器 | **是** | 手动逐张 | 每拍一张立刻给机位/质量反馈 |

> 作业的必做功能不受任何影响。

#### 📋 采集指引（本项目的"防翻车"设计）
**为什么需要它**：相似度是**相对打分**，只跟库内样本比。如果 5 张注册照都是同一个角度、
同一种光照，会出两个问题：① 实时识别时头一转、换个光就"不认识"本人了；
② 库内样本彼此太像时，分数会被挤在高位（例如都在 0.85~0.95），
**绝对值很高但区分度下降**——这就是"相似度到 90% 以上反而不准"的根源。

所以界面内置了一张**机位覆盖表**（`enrollment_guide.py` 自动按**角度**判定，不用你自己判断）。
采集标准采用 **7 机位"人脸黄金录入标准"**：

| # | 机位 | 角度窗口 | 拍法 |
| --- | --- | --- | --- |
| 1 | **正脸** | yaw 0°，平视 | 正对镜头、双眼平视、表情自然、肩膀放松（**先拍这张**，它同时是俯仰基线） |
| 2 | **左半侧** | 左偏 **15°~30°** | 头慢慢向左转，眼睛仍看着镜头（画面里鼻尖偏向右侧） |
| 3 | **右半侧** | 右偏 **15°~30°** | 同上，朝另一边转 |
| 4 | **轻微抬头** | 抬头 **10°~15°** | 下巴微抬、眼睛仍看镜头（能看到一点鼻孔就够了） |
| 5 | **轻微低头** | 低头 **10°~15°** | 下巴微收、眼睛仍看镜头（别真的低头看键盘） |
| 6 | **左大侧** | 左偏 **45°~60°** | 继续转到接近侧脸，能明显看到一侧脸颊（**最能救侧脸识别翻车**） |
| 7 | **右大侧** | 右偏 **45°~60°** | 同上，朝另一边 |
| + | 靠近镜头 | 脸占半屏 | 加分项，模拟贴脸刷手机（不做也能注册） |

这 7 张都是必做（正好满足作业"至少 5 张"的要求，且角度覆盖完整）。每拍一张界面会显示：

- **实测角度**（例如"左/右 +19°、抬/低 +2°"）与它被判成的机位、质量分（0~100）；
- **还差几度**——这是"按角度卡标准"能落地的关键，例如：
  `当前 左/右 +12°（本张会被算成「正脸」）→ 再向左转约 3°（现在 12°，目标 15°~30°）`；
- 是否与已有照片**姿态几乎重复**（容差 8°，因为相邻机位至少差 15°）；
- **下一步拍哪个机位**（按标准顺序：正脸 → 左半侧 → 右半侧 → 抬头 → 低头 → 左大侧 → 右大侧）。

上传图片时，点「🔍 仅检测预览」或直接注册，也会先给出同样的覆盖表
（会先用"第一张平视照"定出参考，再判其余照片）。

##### 角度是怎么算出来的（标定过程）

MTCNN 只给 5 个 2D 关键点，所以角度是**用几何比值反推**的。两个换算系数都是在真实注册照上标定的：

| 关系 | 标定依据 |
| --- | --- |
| `yaw_ratio ≈ 0.55 · tan(θ)` | 旧注册照里 ~30° 侧脸的比值是 0.360、~50° 的是 0.618 → 反解出系数 0.52~0.62 |
| `pitch_offset ≈ 0.90 · sin(φ)` | 现注册照里低头那张比值变化 0.227 → 反解 **14.6°**，与目测"低头 15°"一致 |

因此程序能直接按"15°~30°""45°~60°"这些**角度窗口**判定，也能把实测角度显示给你。
自检里还专门验证了换算精度：给 12° 读出 12.0°、给 22° 读出 22.0°。

> 俯仰（抬头/低头）的**基线取你自己那张正脸照**，而不是人群常数——
> 因为鼻-眼比受脸型与摄像头高度影响很大（同一批照片里正脸 0.59~0.65、侧脸 0.49~0.57）。
> 侧转对俯仰的耦合只做保守补偿（系数 0.3）：实测这个耦合**符号都不稳定**，
> 与其硬拟合，不如让"侧转窗口优先"——侧转判定用标定得更准的 tan 模型。

##### 为什么"抬头 / 低头"这么难录？（以及现在怎么修的）

这是本项目调参过程中最典型的一个坑，用**真实注册照实测**定位到三个原因：

| 照片 | 真实姿态 | yaw | 旧指标"嘴-眼比" | **新指标"鼻-眼比"** | 旧版判定 |
| --- | --- | --- | --- | --- | --- |
| #0 | 正面平视 | −0.039 | 1.116 | **0.526** | 靠近镜头 |
| #1 | 右转 | −0.360 | 1.398 | 0.767 | 头向右转 ✅ |
| #2 | 大角度左转 | +0.618 | 1.608 | 0.879 | 头向左转 ✅ |
| **#3** | **明显抬头** | −0.130 | 0.961（只变 14%） | **0.237（变了 55%）** | ❌ 当成"正面" |
| #4 | 平视 | −0.118 | 1.101 | 0.663 | 靠近镜头 |

1. **用错了特征**：旧版拿"嘴-眼距离"当俯仰指标，真人抬头时它只变化 14%，
   而"鼻尖到双眼的垂直距离"变化 55% —— 后者信噪比高得多，所以现在俯仰**改用鼻-眼比**。
2. **阈值太严**：旧版要求相对偏差 > 0.16 才算抬头，而实测抬头照只有 0.14 → 永远"不够"。
   现在改成"达到 1.0 就算明显"的分数制（`pitch_score`），实测抬头照能到 2.47。
3. **侧转一票否决俯仰**：旧版只要 `|yaw| ≥ 0.175` 就把俯仰**清零**（怕侧转干扰），
   可人抬头时肩颈几乎必然带一点侧转 → 抬头照被误判成侧转。
   现在改成**两个分数比大小，谁大听谁的**，并且先按 `0.6×|yaw|` 补偿掉侧转的虚高。

另外还加了**本人基线自标定**：实时录入时用第一张"平视正面照"标定这个人的鼻-眼比
（不同人的脸型差异很大），之后的抬头/低头按**相对变化**判，比用人群平均值更准。

**实时引导**：幅度不够时不会再只说"已经有一张更好的了"，而是明确告诉你方向还差多少：

```
👉 方向对了，**再抬头一点**（侧转 0.74 / 俯仰 2.06，达到 1.0 就算明显）
```

视频画面里也会叠加英文 HUD（cv2 画不了中文），例如
`yaw=+12 pitch=+0 | NEXT: half_left (yaw 15-30 deg)`，
所以你一边转一边就能看到"还差多少"，不用猜。

## 七、关键实现说明（答辩速查）

### 1. 人脸检测：MTCNN

`face_detector.FaceDetector` 封装 `facenet_pytorch.MTCNN`：

- **三级级联**：P-Net 在图像金字塔上生成候选框 → R-Net 过滤误检 → O-Net 精修框并回归 **5 个关键点**（左右眼、鼻尖、左右嘴角）；
- 关键参数：`min_face_size`（最小人脸）、`thresholds`（三级阈值）、`factor`（金字塔缩放因子）、`keep_all`（是否保留全部人脸）；
- 检测结果按人脸面积**从大到小排序**，"最大的人脸"通常就是画面主角。

### 2. 对齐与裁剪

- 用左右眼连线计算倾角 θ，把图旋转到**双眼水平**（`Image.rotate`），并用同一变换矩阵映射人脸框与关键点；
- 按框 + `margin` 取**正方形**区域（避免缩放时把脸拉扁），再缩放到 **160×160**；
- 经验：对齐能明显提升歪头 / 侧脸时的识别率。

### 3. 特征提取：预训练骨干（本项目两种都实现了）

| 选项 | 来源 | 预训练数据 | 说明 |
| --- | --- | --- | --- |
| `inception_resnet_v1`（**默认**） | facenet-pytorch | VGGFace2（人脸身份） | 人脸专用，识别准确率高 |
| `resnet18` | torchvision | ImageNet（通用物体） | 严格对应"ResNet18 骨干"，但没学过人脸身份，区分力较弱 |

作业原文写的是"facenet-pytorch 的 InceptionResnetV1，骨干网络使用 ResNet18"——这两者在实现上是两条不同路线，因此本项目**把两种骨干都做了**，侧边栏一键切换：

- `InceptionResnetV1(pretrained='vggface2', classify=False)`：直接输出 512 维人脸特征；
- `resnet18(weights=IMAGENET1K_V1)` + `fc = nn.Identity()`：用全局平均池化后的 512 维当作特征。

预处理必须与骨干匹配（否则特征失效）：
- FaceNet：`(x - 127.5) / 128`
- ResNet18：`x/255` 后减 ImageNet 均值除标准差

> ⚠️ 两种骨干的特征空间**不通用**。切换骨干后要**清空并重新注册**人脸库，
> 程序会检测维度/来源不一致并给出提示，避免算出无意义的相似度。

### 4. 相似度与阈值

- 特征做 **L2 归一化**后，余弦相似度 = 向量点积，比对退化成一次矩阵乘法（很快）；
- 相似度范围 `[-1, 1]`，越接近 1 越像；本项目实测：本人不同照片一般 0.6~0.9，不同人一般 < 0.3；
- 判定规则：`最高相似度 ≥ 阈值 → 姓名；否则 → 陌生人`；
- **阈值权衡**（报告里可以画这张图）：
  - 阈值↑ → 误识率低、漏识率高（本人容易被拒）
  - 阈值↓ → 本人好通过、但容易被别人"冒充"成功
- `similarity.py` 还提供 `similarity_stats()` 与 `find_best_threshold()`，用已注册样本自动给出建议阈值。

### 5. 人脸库与持久化

`face_database.FaceDatabase` 用 **pickle** 保存：

```python
{
  "schema_version": 1,
  "meta": {"backbone": "inception_resnet_v1", "embedding_dim": 512, ...},
  "people": {
      "张三": {"embeddings": ndarray(5, 512), "image_paths": [...],
              "created_at": "...", "updated_at": "..."},
  },
}
```

- **原子写盘**：先写 `*.tmp` 再 `os.replace` 替换，避免中途断电损坏人脸库；
- **自动备份**：覆盖前把旧文件复制为 `face_db.bak.pkl`；
- **损坏自愈**：读不出来的库会被改名备份并以空库启动，界面给出提示；
- 一个人的多张注册图以矩阵形式保存，识别时按人汇总（`max` 或 `mean_topk`）。

## 九、常见问题（FAQ）

**Q0：`python app.py` 报 `ModuleNotFoundError: No module named 'numpy'`，或者运行完什么都没有？**

两个原因，分别对应两种修法：

1. **启动方式**：本项目必须用 `streamlit run app.py`，不能用 `python app.py`；
2. **装错解释器**：Windows 上常同时存在多个 Python（python.org 版、uv 托管版、conda 版、Microsoft Store 版）。
   `pip install` 装到了 A 解释器，却用 B 解释器去运行，就会出现"明明装了却说没有"。

**排查三步：**

```bat
py -0p                                   :: 看看机器上有哪些 Python
py -3.11 -c "import sys;print(sys.executable)"   :: 确认解释器路径
py -3.11 -m pip show streamlit           :: 看依赖到底装在了哪个环境
```

**推荐的解决办法（实测最省事）：**

```bat
cd /d D:\人脸识别大作业
uv venv .venv --python 3.11
uv pip install -r requirements.txt
.venv\Scripts\python.exe self_test.py
.venv\Scripts\python.exe -m streamlit run app.py
```

**两个容易连环踩的坑（本项目实测遇到）：**

- `error: externally-managed-environment / This environment is externally managed`：
  说明这个 Python 由 uv 或 conda 托管，pip 被禁止往里面装东西。
  此时**不要**加 `--break-system-packages` 硬装，直接用虚拟环境（`uv venv`）；
- `python -m venv .venv` 之后 `.venv\Scripts\python.exe -m pip` 报 `No module named pip`：
  这类发行版没有 `ensurepip` 轮子，venv 建出来就没有 pip，
  用 `uv venv` 建环境、`uv pip install` 装包即可（uv 自带解析器，不依赖 venv 里的 pip）。

> 另外，裸 `python` 有时会命中 `WindowsApps` 里的**商店占位程序**（执行后毫无反应或弹出应用商店）。
> `run.bat` 因此优先使用 `py -3.11` 这类启动器，而不是裸 `python`。

**Q1：首次运行报"预训练模型加载失败 / 下载超时"？**
需要联网下载权重（InceptionResnetV1 约 110 MB）。可手动下载后放到缓存目录：
- facenet-pytorch：`%USERPROFILE%\.cache\torch\checkpoints`（Linux/macOS 为 `~/.cache/torch/checkpoints`）
- torchvision：`%USERPROFILE%\.cache\torch\hub\checkpoints`

只想先验证代码流程、不在乎精度时，可在代码里把 `pretrained=None`（会走随机初始化权重，相似度没有意义）。

**Q2：CPU 下识别很慢？**
MTCNN 检测是主要瓶颈。可把「最小人脸尺寸」调大、关闭「保留所有人脸」、减少「单张图最多处理几张脸」，或改选 GPU。单张 160×160 的特征提取在 CPU 上通常几十毫秒。

**Q3：摄像头打不开？**
浏览器需授权摄像头；非 localhost 访问时部分浏览器要求 HTTPS。实时识别首次启动视频处理进程要加载模型，等 10~30 秒属正常。

**Q4：中文姓名显示成方块？**
系统缺中文字体。程序会自动尝试 `C:\Windows\Fonts\msyh.ttc` 等常见字体，都不存在时回退到 Pillow 默认字体（中文显示为方块）。可在 `face_detector._CJK_FONT_CANDIDATES` 里加上你机器上的字体路径。

**Q5：换了骨干网络后识别全乱？**
两种骨干的特征空间不同，必须**清空人脸库后重新注册**。程序检测到维度不一致会直接报错提示。

**Q6：多人脸照片怎么办？**
识别时默认最多处理 3 张（可调），结果区会给出逐张人脸的姓名与相似度；注册时若一张图有多张脸，会取**最大**的那张并提示。

**Q7：`face_db.pkl` 能直接分享吗？**
**不要**打开来历不明的 pickle 文件——反序列化会执行文件中的代码，存在安全风险；只加载自己生成的人脸库。人脸数据属于个人敏感信息，演示结束后建议及时清空。
